# LESSONS

追記専用。各エントリは「却下した案 / 決め手 / 覆す条件」。

## 2026-09-22 ZIP の取得方法

- 却下した案: ダウンロードページをブラウザ操作で取得する、または非公開 API を叩く
- 決め手: ダウンロードページは SPA で静的 HTML にリンクがなかったが、JS バンドルのルーティング定義から配布 URL が `files/{年度}/rs/{ファイル名}.zip` と特定できた。ファイル単位の直接取得なら 1 回ずつで済む
- 覆す条件: 配布 URL の形式が変わる、または公式に API が案内される

- 却下した案: Shift_JIS を想定して golang.org/x/text を最初から入れる
- 決め手: 全 15 ファイルが UTF-8（BOM 付き）だった
- 覆す条件: 過去年度や他シート種別が別の文字コードで配布される

## 2026-09-22 `2-1` の合計行と会計別行の持ち方

- 却下した案: (a) 会計別行から再集計して合計を作る、(b) 合計行だけ保持する
- 決め手: 実データで合計行と会計別行の合計は全 18,522 グループで一致したが、公表値と導出値を混ぜると不一致時に原因を追えない。(b) は要望額（会計別行にしかない）と整合チェックの材料を失う。両方保持し、表示は合計行を基準、不一致は Issues に記録して合計は書き換えない
- 覆す条件: 合計行が配布から消える、または不一致が常態化する

## 2026-09-22 「執行が確定した最新の予算年度 N」の決め方

- 決め手: FY2023 の合計行に執行 0 円が 483 件あり、0 円という有効な実績を欠測と取り違える。N はデータセット共通で「事業年度 − 1」とし、非ゼロ執行の最大年度は整合チェック（Notes）に使う
- 覆す条件: 配布版によって執行実績の対象年度が「事業年度 − 1」でなくなる

## 2026-09-22 全事業の読み方（Phase 2）

- 却下した案: (a) 6 ファイルを順に読んで全事業を map に保持する、(b) 中間 JSON や SQLite に落とす、(c) 非連続 ID を検出したら map にフォールバックする

## 2026-09-22 一覧データの配置と JSON 埋め込み

- 却下した案: `data/summary.json` を `fetch()` で読む、`text/template` や文字列連結で index.html を組む

## 2026-09-23 Workers 静的アセットの `.html` の扱い

- 却下した案: (a) `html_handling: auto-trailing-slash`（既定）、(b) `/` を `index.html` に向けるだけの Worker スクリプト
- 決め手: (a) は `list.html` や `p/<ID>.html` への相対リンクを毎回 307 で拡張子なしに飛ばす。`none` にすると `.html` はそのまま返るが `/` が 404 になる。`_redirects` の `/ /index.html 200` で `/` だけリライトすれば Worker スクリプトなしで済む
- 覆す条件: 生成側で拡張子なしのリンクに切り替える、または Workers の `html_handling` に「リダイレクトせず `/` だけ解決」の選択肢が増える

## 2026-09-23 詳細ページの「お金の内訳」の描き方

- 却下した案: (a) 財源と使い道を 2 本の積み上げ棒で描く、(b) 入口の和と現額のずれを吸収する「差額」行を置く、(c) 描画ライブラリを使う、(d) Web フォントで見た目を整える

- 覆す条件: 入口の和が現額と合わない年度のシートが出てくる（そのときは差額行を足す）

## 2026-09-23 ループ検証の判定名

- 却下した案: 「矛盾」（縮減・廃止・終了予定なのに翌年度の当初予算が増えた事業の呼び名）と、兆候の「反映と逆行」、赤の強調
- 決め手: 増額は事業の再編・移管などでも起こり、シートの値だけでは不正や無駄と区別できない。断定の言葉と赤は「判定するサイト」に見せ、見える化サイトの規約（国が作成したかのような態様の禁止）との相性も悪い。「反映要確認」と説明文（「〜だったのに翌年度の当初予算が増えています。事業の再編・移管などの可能性もあります」）、琥珀色にして、人が調べる候補を絞り込む道具という立ち位置を VISION の目的に書いた
- 覆す条件: 再編・移管を ID の系譜などで機械的に除けるようになり、残りが本当に方針と逆の増額だけになる

## 2026-09-23 金額がすべて 0 の事業と親事業の示し方

- 却下した案: (a) 事業名の前方一致で親事業を推定してリンクする、(b) 特記事項の「○○ N 千円の内数」の金額を他事業の予算額と照合して親を推定する、(c) 2-2 の歳出予算項目（所管・組織・項・目）の一致で親を推定する
- 決め手: 1-5 の関連性に「親事業」「子事業」が公式に載っていた。(a) は「ドクターヘリの導入促進（統合補助金分）」が別事業の「ドクターヘリの導入促進」に当たるなど、1-5 と食い違う例が 3 件あった。(b) は金額が 2 つ以上一致すれば 1-5 と同じ親になったが、1 つだけの一致では無関係な事業に当たった。(c) は 1937 の項目が約 20 事業に共通していて親と兄弟をまとめた単位しか分からず、子事業の多く（デジタル庁の個別システム、被災者支援の内訳）では 2-2 の項目自体が空だった。推定で結んだ親を画面に出すと公式の関係のように見えるので、リンクは 1-5 の記載だけにした。2024 年度シートの 1-5 には、2025 年度シートにない親事業の記載が 15 件あり、推定を使わずに済む範囲はシートの年度を広げるほうが伸びた。同じ理由で、0 円事業の説明文からも「〜の可能性」という推測を外した
- 覆す条件: 推定であることを区別して見せる表示が別にでき、(b) の複数金額一致のように 1-5 と矛盾しない根拠が十分な件数そろう

## 2026-09-23 モジュール zip に入らない testdata のファイル名

- 却下した案: (a) testdata のファイル名を配布元のまま残し、go install を諦める、(b) ファイル名を連番などの ASCII に総入れ替えする、(c) v0.1.0 のタグを付け直す
- 決め手: v0.1.0 を切った直後の `go install …@v0.1.0` が「malformed file path … invalid char '・'」で失敗した。モジュール zip はファイル名に文字（Unicode の L 類）以外の記号を許さず、「・」「、」が該当した（12 ファイル）。読み取りは `番号_RS_年度_*.csv` で照合するので、2 文字を抜くだけでコードは変えずに済み、配布元の名前もほぼ読める。プロキシに載ったタグは内容を差し替えられないので、v0.1.0 は go.mod で retract して v0.1.1 を切った
- 覆す条件: モジュール zip が記号入りのファイル名を受け付けるようになる、または testdata を別リポジトリ・別モジュールに出す

## 2026-09-23 コードとテストデータでライセンスが違うときの書き分け

- 決め手: 注記を足した LICENSE では GitHub のライセンス判定（`gh repo view --json licenseInfo`）が `other` になった。MIT の原文だけにすると `mit` と判定された。ライセンスが自動で判定されないと、パッケージの索引サイトでドキュメントが表示されないこともある。データの条件は `testdata/README.md` に書き、README のライセンス節からも触れた
- 覆す条件: ライセンスの自動判定が追記つきの本文も認識するようになる、またはテストデータを別リポジトリに出す

## 2026-09-23 retract した直後の go install の失敗の見分け方

- 却下した案: `go install …@v0.1.1` の失敗を見て v0.1.1 自体が壊れていると判断し、タグを切り直す
- 決め手: 失敗のメッセージは「loading deprecation … @v0.1.0: verifying go.mod … sum.golang.org … 404」で、指定した版ではなく、壊れていた v0.1.0 の go.mod を読みに行って落ちていた。空のモジュールキャッシュ（`GOMODCACHE` を一時ディレクトリにする）では同じコマンドが成功した。手元のキャッシュにある古い版の一覧が原因だったので、このモジュールのキャッシュ（`~/go/pkg/mod/cache/download/<module>`）だけを消して解消した。インストールできるかの確認は、空のキャッシュで行う
- 覆す条件: go コマンドが deprecation を確かめる際に、手元にキャッシュした版の一覧を使わなくなる

## 2026-09-23 最初のリリースページを付けるタグ

- 却下した案: 既にある v0.1.1 のタグにリリースページとバイナリを付ける
- 決め手: サイトのリポジトリへのリンクと `zailoop version` は v0.1.1 の後のコミットなので、v0.1.1 から作ったバイナリには入らない。v0.1.2 を切って最初のリリースにし、バイナリはタグを取り出したクリーンな worktree から `-X main.version=<tag>` を付けて作った（作業ディレクトリには追跡していないバイナリやメモがあるため）。ダウンロードしたアーカイブで、ハッシュの一致と版の表示を確かめた
