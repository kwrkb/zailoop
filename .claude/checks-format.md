# 確認記録の形式

兆候で絞り込んだ事業を、人が裏取りした記録。根拠はシートの外の一次資料（`source`）と、シートの中の別の欄どうしの突き合わせ（`sheet_ref`）の 2 種類。Phase 3c で使う。

- 置き場所はルートの `checks/`（`.gitignore` 済み、コミットしない）。個別企業の契約などが並ぶため
- 1 事業 1 ファイル、`checks/<予算事業ID>.md`
- 製品（`show` / `build`）は `checks/` を読まない。読ませるのは、VISION の非スコープ（外部データとの結合）と設計判断 14 を改訂してから
- 書式の検証: `.claude/check-records.sh checks/*.md`（問題がなければ何も出さず終了コード 0）

## ファイルの形

先頭がヘッダ、最初の空行から後が本文。

```markdown
id: 99999
name: ○○システムの整備
sheet: 2024
sheet: 2025
checked: 2026-09-25
status: 一部
kind: all_zero
kind: zero_with_spending
question: 2-1 がすべて 0 だが、FY2024 に支出はあったか
sheet_ref: 2025 1-2 備考 r5505 | 一致 | FY2024 開発額 82,500 千円。5-1 の府省向け支出と同額
sheet_ref: 2025 5-1 r191910 | 一致 | 府省向け支出 82,500,000 円
source: https://www.example.go.jp/a.pdf#page=2 | 2024 | 候補 | 名称が同じ調達。ID の記載はない
source: https://www.example.go.jp/b.html | 2025? | 一致 | 事業一覧に ID と事業名。存在の確認だけ
next: FY2024 の予算科目
next: 資金移転の会計処理

## 一致した点

- ...

## 一致しなかった点・未解決

- ...
```

## ヘッダ

- 1 行 1 項目。最初の `: ` で項目名と値に分ける
- 行内コメントは書かない（URL に `#page=` が入るため）
- `sheet`・`kind`・`sheet_ref`・`source`・`next` は繰り返してよい。ほかは 1 回だけ

| 項目 | 必須 | 値 |
|---|---|---|
| `id` | ○ | 予算事業ID |
| `name` | ○ | 事業名（照合に使った最新のシートの表記） |
| `sheet` | ○ | 読んだシートの年度（事業年度）。1-5 の親子だけを読んだ年度も含める |
| `checked` | ○ | 確認日（`YYYY-MM-DD`）。確かめ直したら更新する |
| `status` | ○ | `question` への答え（下記） |
| `kind` | ○ | 謎の型（下表）。当てはまるものをすべて |
| `question` | ○ | 謎を 1 行で。`status` はこの問いへの答えなので、答えられる形で書く。新規事業・新規要求は開始年度の予算・契約を問う |
| `sheet_ref` | | シートの中の根拠。2 か所以上の記載の突き合わせ（備考と 5-1、特記事項と 5-1、1-5 の両方向など）か、シートが 0 の理由を自ら書いた記載（増減理由・特記事項・備考）。1 か所の観察（「2-1 はすべて 0」「5-4 に契約がある」）は本文に書く。` \| ` で 3 つ: 場所（`<シート年度> <表> <欄やレコード>`）\| 判定 \| 何を確かめたか |
| `source` | | シートの外の資料。` \| ` で 4 つ: URL \| 資料の年度 \| 判定 \| 何を確かめたか |
| `next` | | 次に確認する資料。1 行 1 件 |

区切りの ` | ` は最後の欄以外に含めない（最後の欄は残り全部）。

### status

`question` に答えられたかどうか。根拠がシートの中（`sheet_ref`）か外（`source`）かは問わない。どちらに拠ったかはヘッダを見ればわかる。

- `説明あり`: 答えが、判定 `一致` の根拠で示された。問いと関係のない残点（支払年度、会計処理など）は `next` に書き、status を下げない
- `一部`: 答えの一部だけ示された。名称・内容は本件と対応するが金額・年度が確定しない（`候補` 止まり）、など
- `未解決`: 答えの根拠がない、または問いに関わる食い違いが説明できない

数えない根拠:

- `kind` の定義をなぞるだけの事実（`zero_with_spending` の事業で「5-1 に支出の記録がある」「5-4 に契約がある」）。問いもこの形にしない

- 事業が存在すること（一覧に ID・名称がある）だけを確かめた資料
- 親事業や兄弟事業についての記載だけの資料（本件の答えにならない）

迷ったら低い方にする。

読み方の決まり:

- 2-1 の FY N の行の増減理由・特記事項は、N+1 の要求についての記載（`docs/data-survey.md`）。FY N の 0 の理由は FY N−1 の行を見る
- シートが自ら書いた 0 の理由に数えるのは 2-1 の増減理由・特記事項、1-2 の備考・事業区分、2-2 の備考。4-1 の評価の文と、増減理由の「新規事業」だけの記載は数えない
- 複数の事業をまとめた資料（合計額しかない）は、本件の答えに数えない
- 要求額・予算案が名称で対応するだけ（`候補`）なら、最大で `一部`
- 版をまたぐ・別の ID と比べる `sheet_ref` の場所は `2024 1-5 r5630 と 2025 1-5 r5130` のように書く

基準の例:

| ID | question の要旨 | status | 理由 |
|---|---|---|---|
| 21280 | FY2024 に支出はあったか | 説明あり | 備考・5-1・落札公示の金額が一致 |
| 21231 | FY2024 に支出はあったか | 説明あり | 備考の FY2024 執行額と公式の契約額が一致（支払の確認は `next`） |
| 7587 | 予算表は 0 だが契約はあるか | 説明あり | 5-4 の契約と調達実績の件名・契約先・概数が一致 |
| 1937 | 0 だが FY2024 の執行はあるか | 説明あり | 特記事項の子別執行額と 5-1 のブロック計が一致（`sheet_ref`） |
| 21232・21249 | FY2024 に支出はあったか | 説明あり | 備考の額と 5-1 が一致（`sheet_ref`）。外の資料の有無で差を付けない |
| 7548 | 0 の理由は何か | 説明あり | 2-1 の増減理由「当年度の支出はない」が 0 と対応（シートが自ら理由を書いている） |
| 7592 | 0 だが研究の契約・支出の実態はあるか | 一部 | 5-4 に契約はあるが、外部資料は要求額の `候補` だけ。7587 と違い調達実績と突き合わせていない |

| 1939 | 特記事項の額と直接支出の差は何か | 未解決 | 76,417,000 円の差が説明できない |

### 判定（`sheet_ref`・`source` 共通）

- `一致`: 照合した点（金額・件名・契約先など）が合う
- `一部`: 一部だけ合う（例: 1 件の契約が 2 つのシステムにまたがる、500 円の差）。どこが合わないかを最後の欄に書く
- `不一致`: 合わない
- `候補`: 名称・内容は対応するが、資料に予算事業ID がなく同一と言い切れない

### 資料の年度（`source`）

資料の数字がどの予算年度のものか。`2024`、範囲は `2023-2025`、飛び飛びは `2017,2025`。

- 公表日・更新日ではない。公表日は本文に書く
- 推定なら末尾に `?`（`2025?`）
- 数字がない資料（要綱・一覧）は、その資料が適用される年度。わからなければ `不明`

### kind

既存の兆候は `internal/lifecycle/signals.go` のキーをそのまま使う。シートだけで判定できる型は、兆候に戻す候補になる。

| 値 | 意味 | シートだけで判定できるか |
|---|---|---|
| `reflection_contradicted` など | 既存の兆候（Signal のキー） | できる |
| `all_zero` | 2-1 の金額がすべて 0 | できる |
| `zero_with_spending` | 2-1 はすべて 0 だが、5-1 の支出先・5-4 の契約・1-2 の備考のどれかに非ゼロの金額がある | できる（備考は書式しだい） |
| `amount_revised` | シート間で同じ予算年度の金額が変わった | できる |
| `link_revised` | 1-5 の親子の記載がシート間で変わった（前のシートにだけある、など） | できる |
| `id_moved` | 旧 ID からの移行がシートに書いてある。旧集約シートについての定型の注記だけでは付けない（移行より後に始まった事業にも同じ文面がある）。開始年度が移行より前か、備考に移行前の年度の額がある場合に付ける | 備考の書式しだい |
| `external_mismatch` | シートの金額と外部資料の金額が食い違う | できない |
| `other` | 上のどれでもない（本文に書く） | |

関係を推定する型は作らない（例:「子は 0 で金額は親が持つ」）。シートに書いてあることだけで型を決める（VISION 設計判断 14）。

## 本文

自由記述。見出しは次を基本にする。

- `## シートの記載`: レコード番号、備考・増減理由・5-4 などの原文の要点
- `## 一致した点`
- `## 一致しなかった点・未解決`
- `## 確かめられなかった資料`: 本文を確認できなかった資料（取得に失敗した、検索結果だけ、PDF のテキストが取れない、メモに URL がない）。`source` にはしない

金額は円単位で書き、予算・契約・支出の区別を落とさない。推測は推測と書く。
