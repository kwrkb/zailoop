# データ調査（Phase 1a）: 行政事業レビュー見える化サイト 2024年度 CSV

調査日: 2026-09-22 / 対象: 2024年度レビューシート CSV（データ基準日 2025-02-14）
出典: 行政事業レビュー見える化サイトのデータを加工して作成（加工: zailoop / kwrkb）。データ: https://rssystem.go.jp/ 、公共データ利用規約 第1.0版（PDL1.0）

## 0. 結論（先に要点）

- **予算ライフサイクル 6 段階はすべて 1 枚のレビューシート内で閉じる。** 要求・成立・執行・決算は `2-1`、評価と翌年度反映は `4-1`、成果目標と実績は `3-1` にあり、いずれも `予算事業ID` で結合できる。Phase 1 の「1事業を1画面」は実現可能。
- **年度をまたぐ追跡（Phase 3）も見込みあり。** `予算事業ID` は年度をまたいで同一事業を指す永続 ID である（2024→2025 で 5,664 件中 5,231 件が同一 ID で継続。消えた 433 件のうち 340 件は 2023 年度終了予定事業）。
- **実装上の難所は 3 つ。** (a) `2-1` は「合計行 + 会計別行」の 2 層構造、(b) 執行実績は「事業年度 − 1」までしかない（2024 年度シートの執行は FY2023 が最新）、(c) `5-1` は 3 階層のネストを 1 表に平坦化している。

## 1. 取得方法

- ダウンロードページ（`/download-csv/2024`）は SPA で、静的 HTML には ZIP リンクがない。JS バンドル内のルーティング定義から、配布 URL は次の形式と判明した。
  - `https://rssystem.go.jp/files/{年度}/rs/{ファイル名}.zip`（ファイル名は下表の 15 種。URL エンコードが必要）
  - 各 ZIP は CSV 1 本を含む。年度単位の一括 ZIP はない。
- 2025 年度も同じ 15 ファイル構成で、`1-2` のヘッダは 2024 と完全一致した。
- 利用規約は「公共データ利用規約（第1.0版）（PDL1.0）」準拠。出典記載が必須で、加工した場合は「〜のデータを加工して作成」の旨を書く。法人番号（国税庁）と法令名（e-Gov）は外部提供元の条件に従う。

## 3. キーと結合

- **一意キーは `予算事業ID`**（整数文字列、1〜21059、欠番あり）。2024 年度の事業数は **5,664**。
- 全 15 ファイルの `予算事業ID` は `1-2` の集合と完全一致した（どのファイルにも `1-2` にない ID はなく、`1-2` にあってどこかのファイルに欠ける ID もない。行のない事業は空欄 1 行で存在する）。
- 結合は `予算事業ID` のみで十分。`事業年度` は同一年度の CSV 内では定数で、複数年度を扱うとき（Phase 3）に複合キー `(事業年度, 予算事業ID)` になる。
- `1-2` の `旧事業番号` は 5,948 件中 116 件しか埋まっておらず（2025 年度は 7 件）、年度間の追跡キーには使えない。追跡は `予算事業ID` で行う。
- **`1-2` の重複行（255 ID）は `主要経費` だけが異なる。** 主要経費が複数ある事業が 1 行ずつ展開されている。事業マスタとして使うときは `主要経費` を集約する。
- **`4-1` の重複行（28 ID）は「過去に受けた指摘事項」「その他の指摘事項」の列だけが異なる。** 評価本体（点検結果・所見・反映状況・反映額）は同一なので、指摘事項を配列に畳めば 1:1 になる（ただし `反映額（特別会計）` が異なる ID が 1 件あり、要注意）。

## 4. ライフサイクル各段階と列の対応

### 4.1 `2-1` の構造（最重要）

この節と §4.2・§6 は 2024・2025 年度シートの形式。2026 年度シートで列名・行の構造・0 の書き方・執行率の単位が変わった（§9）。

- 1 事業 × 1 予算年度につき **「合計行」1 行 + 「会計別行」1 行以上** で構成される。
  - 合計行: `会計区分` が空。`当初予算（合計）` 〜 `翌年度要求額（合計）`（列 14〜22）が埋まり、列 28〜42 は空。
  - 会計別行: `会計区分`（一般会計/特別会計）と `会計`・`勘定` が入り、列 28〜42（`当初予算, 第1〜5次補正予算, 前年度から繰越し, 予備費等1〜4, 歳出予算現額, 執行額, 翌年度要求額, 要望額`）が埋まる。
  - 合計行の値 = 会計別行の合計であることを全 18,522 グループで検証し、**不一致 0 件**。合計行が空で二重に存在するグループが 2 件あった（`6201/2022`, `18717/2024`）。
- `予算年度` は **2021〜2024 の 4 年分**（サイトの注記どおり「過去データは 2021 年度以降」）。4 年そろう事業 3,776 件、1 年のみ 661 件（新規事業）。
- **執行額は予算年度 2024 では全件 0。** 2024 年度シートは FY2024 進行中（2024 年 8 月頃）に作成されるため、執行実績の最新は **予算年度 2023**。
- `翌年度要求額（合計）` は予算年度 2024 の行で全 5,664 件に値があり、これが **FY2025 概算要求**。予算年度 2023 の行の同列が FY2024 概算要求（= FY2024 当初予算の「要求」側）。
- `要望額` は要求額とは別枠（重要政策推進枠などの要望）で、2024 年度 1,511 行に値がある。`主な増減理由` に「重要政策推進枠：…」のように枠名が書かれる。
- `執行率` = `執行額 / 歳出予算現額` を小数（0.797 など）で保持。全 11,652 行で再計算と一致。

## 5. 金額の単位と表記

- 金額はすべて **円単位の整数**（例: 当初予算 28,854,000）。千円・百万円ではない。予算年度 2024 の当初予算（合計）を全事業で足すと約 121 兆円で、一般会計・特別会計の規模と整合する。
- 桁区切りカンマなし。ただし `2-1` の `翌年度要求額（合計）` だけは `34482000.0` のように小数点付き文字列。
- `執行率`・`達成率` は小数または整数の文字列。`3-1` の年度列は数値も文字列（`1` = 目標年度フラグ）も入る。
- `反映額` は負値（減額）で記入。

## 6. データ品質で気づいた点

1. **`5-1` の数値列に末尾スペース**（`金額` 98,159 件、`法人番号` 134,911 件など）。他ファイルにはない。パーサで `TrimSpace` 必須。
2. **`執行額 > 歳出予算現額` が 468 グループ**（予算年度 ≤ 2023 の合計行）。大半は `現額 = 0` で執行だけある事業で、予算が別事業に一括計上されているケースとみられる。導出した不用額が負になるので、`現額 = 0` のときは不用額を「算出不能」と表示する。
3. **`翌年度繰越 > 現額 − 執行` が 198 グループ**。同様に不用額が負になる。原因は未特定。
4. **空欄と 0 の区別。** `2-1` の合計行は値が「空」か「整数」のどちらかで、0 は明示的に `0`。空はその年度の行が存在しないケース（新規事業の過去年度など）。2026 年度シートでは 0 が空欄で書かれる（§9）。
5. **ダッシュ表記の揺れ。** `4-1` の自由記述に `-`, `ー`, `－`, `--`, `ｰ`, `―`, `‐` が混在（「該当なし」の意）。表示時は空扱いに正規化する。
6. **`3-1` の `アウトカムの期間` に `3.長期` と `長期` が混在**（後者 8 件）。
7. **`1-2` の `事業開始年度`・`事業終了（予定）年度` は空が多い**（終了予定なしの事業は空）。
8. **`5-1` は 3 階層を平坦化**しており、同じ支出先について「合計行」（`支出先の合計支出額` あり）と「契約行」（`金額` あり）が別行になる。単純合計すると二重計上になる。
9. **`4-1` の `事業所管部局による点検・改善ー点検結果` は 413 件が空**、外部有識者点検は 3,837 件が「対象外」。評価段階は事業によって薄い。
10. ファイル名に全角記号（`・`、`、`）を含むため、URL エンコードとファイルシステム上の扱いに注意。
11. **金額欄がすべて 0 の事業がある**（2025 年度シートで 192 件。全予算年度の当初・補正・現額・執行・翌年度要求が 0）。多くは予算が親事業にまとめて計上される「内数」の事業で、`2-1` の `その他特記事項` に「○○補助金 N 千円の内数」と書かれる。親事業は `1-5` の `関連性` = `親事業` で分かる（192 件中 60 件。親側には同じ組が `子事業` として載る）。2024 年度シートの `1-5` にだけ親事業の記載がある事業が別に 15 件ある（被災者支援総合交付金の内訳 13 件など）。残りは、ID 4 にシートを一括して作成していたと備考にあるデジタル庁の個別システム、国庫債務負担行為で後年度に支出する防衛装備、理由の記載がない拠出金などで、`1-5` からは親を特定できない。
12. **`1-5` の `関連性` の値**（2025 年度）: `その他関連元`/`その他関連先`、`運用交付先セグメントシート`、`子事業`/`親事業`、`基金造成した基金シート`、`統合元`/`統合先`、`分割元`/`分割先`。関連事業 ID の約 4 分の 1（2025 年度 1,045 件中 295 件）は基金シートなどレビューシートのない事業を指し、`1-2` にない。
13. **`1-2` の `備考` は自由記述で、2025 年度は 5,794 事業中 2,231 件が埋まっている**（2024 年度は 5,664 件中 1,126 件）。デジタル庁の個別システムでは過年度の執行額（千円単位）と、2023 年度まで ID 4 に一括でシートを作っていた経緯が書かれる（金額がすべて 0 のデジタル庁 73 件中 67 件に備考があり、66 件が ID 4 に触れる）。補正予算に伴うシート改訂の日付と更新箇所が書かれる事業も多い。主要経費で重複する行どうしで `備考`・`事業概要URL` が食い違う事業はない（両年度）。`事業概要URL` は 2025 年度 3,031 件で、すべて単一の http(s) URL。
14. **`5-4` は全事業に行があり、契約のない事業は空欄 1 行**（2025 年度 9,716 行・5,794 ID、契約の記載がある事業は 532 件、1 事業最大 81 件）。予算事業ID は連続・昇順で、マージ読みに加えられる。契約先だけ・契約額だけの行もあるので、読み取る列のどれかが埋まっていれば残す。`支出先ブロック` は 5-1 のブロック記号に対応する。契約額は `2-1` の執行額や `5-1` の支出額とは別の欄（金額がすべて 0 の防衛装備に、100 億円を超える契約の記載がある例がある）。
15. **`1-2` の `備考` にある過年度の執行額は、デジタル庁の個別システムだけが定型で書く**（「「開発・整備関連」／執行額：YYYY年度 N千円、…」。2025 年度 195 件・2024 年度 164 件、すべてデジタル庁）。全角・半角の記号（`／`・`｢｣`・NBSP）と、無い年度の `ー` が混じる。「執行額」を含む備考はほかに 2025 年度で約 390 件あるが、ほとんどは「予算額執行額表の補正予算の追記」という更新の記録で金額はない。定型以外で執行額・決算額に金額を添えた備考は 18 件（文部科学省 11 件など）で、書式が揃わない。定型の FY(N−1) の合計を、`5-2` で `担当組織からの支出` が TRUE のブロックの `ブロックの合計支出額` の和と比べると、2025 年度は 195 件中 一致 156、`5-2` の `国自らが支出する間接経費の金額` を足して一致 7、不一致 12、備考の FY2024 がすべて `ー` 16、5-1 に該当ブロックなし 2、FY2024 の記載なし 2（`ー` と 5-1 の未記載は 0 円とみなさず、照合しない。足すブロックの一部だけが未記載でも照合しない。2024 年度シートの 20190 は 4 ブロックのうち D の `ブロックの合計支出額` が空欄で、残り 3 ブロックの和は備考と合う）。備考は項目ごとに千円未満を丸めているため、項目数 × 1,000 円までの差は一致とみなす。不一致 12 件のうち 7 件は差が 1% 未満で、`2-1` の執行額は備考と合う（5-1 が小さいのが 6 件、大きいのが 5543）。5-1 に該当ブロックがない 20966 は、備考が現行システムの参考額と明記したもので、定型が参考情報も拾う例。差が大きいのは 5 件（20087・20203 は 5-1 と 2-1 が備考を大きく上回り、20187・21048 は備考と 2-1 が合って 5-1 だけ違う、6561 は 5-1 と 2-1 が備考を上回る）。2024 年度シートでは 164 件中 98 件の `2-1` に FY2023 の執行がなく（ID 4 に一括でシートを作っていた時期）、備考と 5-1 がシート内で唯一の突き合わせになる。照合は `.claude/remarks-match.go` で再現できる

## 7. 表示方式の提案

**CLI のテキスト出力を先に作り、同じ構造体から静的 HTML を生成する 2 段構え**を提案する。

- Phase 1b では `zailoop show <予算事業ID>` で 6 段階を縦に並べた表を標準出力に出す。テストしやすく、対応表の検証がそのまま golden test になる。
- 同じ `Lifecycle` 構造体から `zailoop html <ID> -o out.html` で単一ファイルの静的 HTML を出す。Phase 2 以降の横断ダッシュボードは「全事業分の HTML または JSON を生成して静的配信」に自然に拡張できる。
- Web サーバは Phase 1 では持たない（デプロイ・定期実行はスコープ外）。

## 8. Phase 1b への申し送り

- 文字コード変換は不要。**外部依存なし（stdlib のみ）で実装できる見込み。**
- 取得スクリプトは 15 ファイルを 1 回ずつ取得し、既存ファイルがあればスキップする。年度は引数化する（2025 年度も同構成）。
- パーサは `encoding/csv` に BOM 除去と `TrimSpace` を足す。`2-1` は合計行と会計別行を分けて読む。
- 「最新の確定年度 N = 事業年度 − 1」を定数ではなくデータ（執行額が非ゼロの最大予算年度）から決める。
- 不用額の導出は `現額 = 0` のときに「—」を出す。

## 9. 2026 年度シートの変更（2026-11-23 取得）

2026 年度シートは 15 ファイル・5,826 事業（1-2 は 6,105 行）。予算事業ID は全ファイルで連続・昇順のままで、`Each` のマージ読みはそのまま使える。改行が CRLF から LF になった（`encoding/csv` では影響なし）。15 ファイル中 11 ファイルはヘッダが 2025 年度と同じで、違いは次のとおり。読み取りは `internal/rs/csv.go` の `columnAliases`（旧列名 → 新列名）で新旧どちらも読む。

**翌年度繰越の導出。** 2025 年度シートでは、同じシートの「FY N の `翌年度への繰越し(合計）`」と「FY N+1 の `前年度からの繰越し（合計）`」が 17,241 組すべてで一致した（うち 4,376 組が非 0）。シートをまたいでも、2025 年度シートの FY2024 の翌年度繰越と 2026 年度シートの FY2025 の前年度から繰越しは 4,814 組中 4,769 組で一致した（不一致 45 組は改訂とみられる）。そこで 2026 年度シートでは FY N+1 の前年度から繰越しを FY N の翌年度繰越とする（ユーザー確認済み）。FY N+1 の行がない事業（FY2025 はあって FY2026 がない 25 事業）は繰越が分からないので、不用相当額を「算出不能」にする。2025 年度シートでは、FY2024 の行がある事業はすべて FY2025 の行も持っていた。

**兆候への影響。** 最新シートが 2025 の事業（5,794）と 2026 の事業（5,826）で該当率を比べると、要求と成立の乖離 6.4% → 8.6%、成果未達 15.4% → 19.7%、要求ゼロ査定 3.4% → 4.3%、シート間の改訂 1.2% → 2.0% が上がった。成果未達の増加は主に上の 3-1 の達成率の書き方による。要求ゼロ査定の 249 事業は、FY2026 当初が空欄 206・`0` 43 で、2-2 にも FY2026 当初の内訳がなく、空欄を 0 と読んだことによる誤検出ではない。シート間の改訂は 2024→2025 の 70 事業をすべて含み、2025→2026 で 52 事業が増えた。執行 0・現額 > 0 の年度の執行率は、2025 年度シートでは 236 件すべて空欄、2026 年度シートでは 73 件が `0` で、この 73 件は「低執行」に入る。

**取り込んだ結果。** 2026 年度シート単独で、全事業の読み取りで予算年度ごとの Issue（合計の不一致・重複など）は 0 件（2025 年度も 0 件）。`--years 2024,2025,2026` で 6,732 事業。2025→2026 のループ検証は、縮減 138 整合 / 39 反映要確認、廃止 19 / 1、終了予定 540 / 4。`--years 2024,2025` の出力は、取り込み前と生成時刻・用語の説明文以外すべて一致した。
